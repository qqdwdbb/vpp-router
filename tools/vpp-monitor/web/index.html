网卡收包

轮询：线程不停查询网卡，延迟最低，所在 CPU 始终占满。中断：没有包时线程休眠，由网卡中断唤醒，省电但每批包多一点延迟。自适应：流量小时等中断，流量大时自动转为轮询，一般选它。不支持中断的网卡会拒绝，保持原来的方式。修改立即生效，VPP 重启后自动恢复；“缺省”是安装器的设置（router.env 的 RX_MODE），选它时现在的方式不变，下次 VPP 启动时生效。

CPU 频率

Linux 的 cpufreq 调速器，每组共用频率的 CPU 一个。performance 固定最高频率，VPP 轮询时延迟最稳；ondemand、schedutil 按负载升降频，省电，但流量突然增大时升频要几毫秒，可能少量丢包。修改立即生效，开机时由 vpp-system 重新设置；“缺省”是系统自己的设置，选它时现在的调速器不变。

会话超时（秒）

连接多久没有包就回收它的会话。TCP 已建立的连接默认 7440 秒，太长时空闲连接长期占着会话表；太短时长时间不说话的连接（SSH、推送）会被断开。修改立即生效，写入 。

会话表

会话数和用户数是每个线程的上限（主线程和每个 worker 各一份），每个用户的会话数是一个局域网地址最多同时占用的会话。表满时新连接被丢弃。表越大占用 VPP 主堆内存越多，内存不够时插件启用失败，VPP 会自动恢复旧值。要重启 VPP，60 秒内不确认就恢复。

出口

规则和默认出口把流量送到这里的出口。VPP 接口的出口可以设置下一跳：可以是它的网关，也可以是经它能到达的其他地址。同一个接口要走不同的下一跳时，给出口起个名称，一个接口可以有多个出口，各用各的下一跳；名称留空就是接口本身的出口。用 DHCP 网关时下一跳跟着租约变，这样的出口只能做默认出口。有规则在用这个出口时，修改会同时改这些规则并重启 Gate，60 秒内要确认。Linux 出口和代理的下一跳由 Gate 的设备配置生成，这里只显示。
